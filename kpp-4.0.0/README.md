# Workshop (v 4.0.0)

Терминал производственного персонала для учёта рабочего времени и регистрации изготовления оконных конструкций (прямоугольных и полукруглых рам/створок).

## Описание

Настольное приложение на Python с графическим интерфейсом (Tkinter), построенное по слоистой архитектуре с разделением ответственности между слоем данных, бизнес-логикой и UI:

- **Учёт работников** — регистрация начала и окончания смены, перемещение между рабочими местами с проверкой лимита мест (`RAB_MAX`), автоматическое закрытие «зависших» сессий за прошлые дни.
- **Регистрация деталей и изделий** — сканирование штрих-кода, проверка принадлежности к разрешённой группе рабочего места (`GR`), защита от дубликатов (с возможностью повторного сканирования для просмотра чертежа и размеров), расчёт габаритов, периметра и площади (включая арочные/полукруглые конструкции).
- **Векторный рендерер конструкций** — отрисовка чертежей ПВХ-конструкций прямо на `tk.Canvas` из данных CCALC (таблицы BASE7/BASE8/BASE3/BASE4/BASE6): профили с цветами, имитация заполнений, выделение активных деталей и изделий.
- **Статистика смены** — подсчёт количества уникальных изделий, суммарного периметра (м) и площади (м²) за текущую смену.
- **Мониторинг и отказоустойчивость** — фоновая проверка состояния двух баз данных (workshop и CCALC), визуальный индикатор статуса, автоматическое управление транзакциями и автовыключение ПК при простое в конце дня.

### Слои приложения

| Слой / Модуль | Назначение |
|---------------|------------|
| `config.py` / `config.ini` | Чтение настроек из INI-файла, автоопределение IP-адреса терминала по маршруту до сервера БД |
| `models.py` | Модели `Workplace`, `WorkerSession`, `Detal`, `Dimensions`, `ShiftStats`, `ActionResult`, `DetailGroup` и правила групп |
| `database/` | Класс `Database` с контекстным менеджером `transaction()` (авто-`commit`/`rollback`) и `WorkshopRepository` |
| `services/` | Независимая от Tkinter бизнес-логика (`WorkerService`, `DetalService`), возвращающая `ActionResult` |
| `ui/` | Виджеты (`DetalInfoPanel`, `StatsPanel`, `WorkersTablePanel`, `StatusIndicator`) и координатор `Application` |
| `ui/construction_preview.py` | Векторный рендерер конструкций: `ConstructionViewerPanel`, `fetch_construction_geometry()`, `check_ccalc_connection()` |

## Конфигурация и пути (`config.ini`)

Настройки вынесены во внешний файл `config.ini` (при его отсутствии используются значения по умолчанию из `config.py`):

- **База данных MySQL (`[database]`):**
  - Хост: `192.168.0.10` (`host_dev = 192.168.88.200` для хоста `cybstation`), порт `3306`
  - Пользователь / Пароль / БД: `workshop` / `w0rK5h0p` / `workshop` (`utf8`)
  - Основные таблицы: `WORKER`, `WORKPLACE`, `WORKER_TIME`, `CCALC`, `DE TAL_TIME`
- **База данных CCALC (`[ccalc_database]`):**
  - По умолчанию наследует параметры из `[database]`; имя БД: `CCALC`
  - Таблицы конструкций: `BASE7` (детали конструкции, BARCODE, MATCOLOR), `BASE8` (изделия), `BASE3`, `BASE4` (цвета профилей), `BASE6`
- **Параметры приложения (`[app]`):**
  - Версия: `v 3.7.0` (конфигурируемая)
  - Код выключения ПК (`code_poweroff = 12345`), префикс сотрудника (`prefix_worker = 2200`)
  - Интервал автообновления (`auto_update_ms = 60000` мс) и повторного подключения (`reconnect_ms = 5000` мс)
  - Опциональное ручное переопределение IP терминала (`my_ip`)
- **Параметры простоя (`[idle]`):**
  - Час начала контроля (`after_hour = 17`), таймаут (`timeout_sec = 3600` сек), интервал проверки (`check_ms = 60000`)
- **Логирование (`log.py`):**
  - Логи сохраняются локально в `./logs/{Имя_рабочего_места}.log`.
  - При смене даты предыдущий файл архивируется с суффиксом `_ДД.ММ.ГГ.log` (хранятся последние **3 архива**).

## Запуск

```bash
python3 main.py
```

При запуске открывается модальное окно подключения к БД (`ConnectionDialog`) с поддержкой сканирования кода выключения `12345` ещё до установки связи. После успешного соединения загружается интерфейс рабочего места, закрываются незавершённые сессии за предыдущие дни и запускаются фоновые циклы: автообновление (каждые 60 с), проверка простоя (каждые 60 с) и мониторинг состояния БД (каждые 5 с).

## Управление и бизнес-логика

| Действие / Событие | Описание работы |
|--------------------|-----------------|
| **Вход / выход сотрудника** | Сканирование штрих-кода с префиксом `2200`: открывает сессию на текущем месте, закрывает при повторном сканировании или переводит с другого рабочего места (при наличии свободных слотов `RAB_MAX`). |
| **Регистрация детали** | Сканирование кода детали из `CCALC`. Для рабочих мест `GR` 1–2 разрешены только рамы (`r`), для `GR` 3–4 — только створки (`s`), для `GR` 5–6 — оба типа с контролем уникальности по `BCI`. Группа `3` (импост) игнорируется. При сканировании дубля на экран выводятся карточка и чертёж изделия без повторной записи в БД. |
| **Расчёт геометрии** | Из длин деталей вычитается `6 мм`. Для прямоугольных изделий (`ORIENT` = `В` и `П`) считается $P = 2(w + h)$, $S = w \cdot h$. Для полукруглых (`DUGA = 1`, `ORIENT` = `В` и `Н`) считается $P = L_Н + L_В$, $S = \frac{L_Н^2 \cdot \pi}{8}$. |
| **Индикатор статуса** | Квадрат в левом нижнем углу: **зелёный** — обе БД (workshop и CCALC) доступны; **жёлтый** — нет доступа к CCALC; **красный** — потеряна связь с БД workshop. |
| **Выключение ПК** | Сканирование кода `12345` закрывает все активные сессии на рабочем месте и выключает компьютер (`systemctl poweroff` / `shutdown -S`). |
| **Автовыключение по простою** | После `17:00`, если на рабочем месте есть открытые сессии, но в течение `1 часа` не зарегистрировано ни одной детали, сессии принудительно закрываются временем последней активности и ПК выключается. |
